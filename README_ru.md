## 🌟 Ключевые особенности

* **🎯 Глобальное масштабирование разрешения:** Изменение внутреннего разрешения рендеринга для всех 3D VR приложений.
* **⚡ Управление уровнями мощности GPU:** Ручная установка `max_pwrlevel` и `min_pwrlevel` GPU для фиксации состояний производительности (от максимальной производительности до энергосбережения).
* **📐 Расширенные настройки рендеринга:**
  * **Stencil Mesh:** Оптимизация ресурсов GPU за счет предотвращения рендеринга скрытых пикселей.
  * **Foveated Rendering:** Оптимизация производительности за счет концентрации разрешения в центральной зоне фокуса.
  * **Texture FOV:** Тонкая настройка поля зрения для текстур глаз.
* **🔄 Сброс в один клик:** Выделенная кнопка «Restore Default» для мгновенного возврата всех настроек к безопасным стандартным значениям Pico.
* **🧩 Сохранение после перезагрузки:** Встроенная поддержка модуля LSPosed (Xposed) для автоматического повторного применения уровней мощности GPU после каждой перезагрузки.
* **❓ Интерактивная справка:** Встроенная документация для каждого параметра с объяснением технических деталей и компромиссов.
* **📊 Оптимизированные пресеты:** Выбор из предустановленных значений, оптимизированных для производительности или четкости:
  * **384px**: Ультра-производительность
  * **752px**: Производительность
  * **1504px**: По умолчанию
  * **2160px**: Родное разрешение
  * **2448px**: Специально для Pico
  * **2816px**: Сглаживание (Anti-aliasing)
* **🔍 Проверка в реальном времени:** Автоматическая проверка успешности изменений в базе данных перед перезагрузкой.
* **🛠️ Современный интерфейс:** Адаптивный интерфейс на Jetpack Compose, оптимизированный для горизонтального режима VR с двухколоночным макетом.
* **🌐 Многоязычная поддержка:** Полная локализация на 27 языков с профессиональной технической терминологией.
* **🔐 Безопасность Root:** Использование команд `content` для безопасного изменения конфигурации PVR системы.

## ⛏️ Предварительные условия

* **Устройство:** Шлем Pico 4 (поддерживаются прошивки Phoenix/Китай).
* **Суперпользователь:** Требуются **[Root-права](https://github.com/chaixshot/more-picohaxx)** для применения изменений к системным файлам.
* **Среда:** Должен быть установлен и активен **[LSPosed Framework](https://github.com/JingMatrix/Vector/releases/tag/v2.0)**.
* **Разрешение:** Предоставьте root-доступ при запросе от приложения.
* **Область LSPosed:** Убедитесь, что в области действия модуля LSPosed выбран `System Framework (android)`.

## 📐 Как использовать?

1. **Скачайте и установите** актуальную версию `Pico3dResolution.apk`.
2. **Откройте приложение** и предоставьте права **Root/Суперпользователя** по запросу.
3. **Выберите целевое разрешение** и/или **уровни мощности GPU** в раскрывающихся меню.
4. **Нажмите «Apply»**.
    * Если были изменены настройки разрешения/рендеринга, приложение отобразит **«Apply & Reboot»**, и шлем перезагрузится.
    * Если были изменены только **уровни мощности GPU**, отобразится **«Apply»**, и изменения вступят в силу немедленно без перезагрузки.
5. **(Опционально) Автоприменение при загрузке:** Чтобы сохранить активными уровни мощности GPU после перезагрузки, включите модуль в приложении **LSPosed Manager**.
6. **Дождитесь завершения процесса**. Ваши новые настройки активны!

## ⁉️ FAQ / Устранение неполадок

* **Почему требуется перезагрузка?**
  * Служба Pico VR и композитор выделяют свои внутренние буферы рендеринга только при запуске. Перезагрузка необходима, чтобы заставить систему прочитать новые значения `sdk_eyebuffer` из базы данных.
* **Повлияет ли это на производительность?**
  * Да. Более высокое разрешение (например, 2160px или 2816px) значительно увеличивает нагрузку на GPU. В некоторых играх может наблюдаться просадка кадров или повышенный нагрев.
* **Как проверить изменения?**
  * Вы можете использовать **PICO Metrics Tool**, чтобы увидеть активные значения «EBW» (Eye Buffer Width) и «EBH» (Eye Buffer Height) в реальном времени внутри шлема.

## 🛠️ Технические подробности

### Как это работает

* **Разрешение и рендеринг:** Приложение использует root-доступ для изменения базы данных конфигурации PVR системы (`/data/user_de/0/com.pvr.configuration/databases/config.db`). Оно обращается к параметрам `sdk_eyebuffer`, `sdk_enableFFRBySYS`, `sdk_stencilMeshStatus` и `sdk_EyeTextureFov` в таблицах `RuleBean` и `ConfigBean`.
* **Производительность GPU:** Приложение изменяет sysfs-узлы ядра `/sys/class/kgsl/kgsl-3d0/max_pwrlevel` и `min_pwrlevel` для принудительной фиксации частотных состояний GPU.
* **Восстановление при загрузке:** Встроенный модуль LSPosed перехватывает процесс `system_server` для вызова службы восстановления приложения через запрос к `ContentProvider` сразу после завершения загрузки устройства.
